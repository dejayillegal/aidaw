# ADR010: Continuous native rendering with a bounded WAV destination

Status: accepted for the direct WAV path; physical Android qualification remains blocked.

## Problem

The existing Blob/mastering export budgets 32–40 bytes per frame, retaining native stereo PCM plus output/mastering copies. Reference-length 48 kHz/24-bit exports exceed the unchanged 256 MiB guard before rendering. Raising the guard hides allocation pressure. Rendering separate OfflineAudioContexts would reset insert/return state and break tails, deterministic summation and live/offline processor identity.

## Decision

Retain one continuous OfflineAudioContext and the existing two-second audio-clock scheduling windows, shared voice/insert/return processors, ordered sums and retirement logic. After rendering, copy only bounded channel windows into the same PCM quantizer used by the legacy Blob API. Await each destination write; each bridge payload is at most 192 KiB before base64. Android uses the existing SAF plugin's begin/append/finish/read-back protocol. Compatible browsers expose a separate 48 kHz/24-bit direct-file action; browsers without the file API retain the existing bounded Blob option.

The direct path's 256 MiB budget includes stereo Float32 output, declared delay/impulse capacities and explicit encoding/bridge reserves. It does not retain a whole encoded WAV. This is a **working-buffer budget**, not a total process memory guarantee or a constant-memory renderer. Native output still grows with duration. The browser process measurements are recorded separately; Android memory limits require hardware evidence. Configurations above the guard fail before allocation without changing rate, duration, bit depth, devices or score. Mastered Blob exports retain their own original stricter budget.

Keep at least eight seconds of tail. Extend that duration for the current supported static serial delay/reverb settings and enabled sends/returns: delay feedback to a modeled relative −80 dB and reverb decay from T60 to T80, including predelay. Sum serial contributions conservatively. This is not proof for arbitrary native devices, future automation or live acoustic decay. The same policy feeds raw, Blob and direct output length.

Cancellation observes the signal at render windows and encoder writes. Native OfflineAudioContext has no cancellation API: disconnect the output, resume/drain it, and retain the busy reservation until it settles. A stalled drain remains an explicit restart condition. Abort partial destinations after pending writes finish. Disable cancellation during final file commit/read-back so a committed verified file cannot be mislabeled discarded. Expired writer callbacks reject rather than writing into a later session.

## Preservation and migration

No project schema, conversion descriptor, XML, IndexedDB or history migration. Export snapshots are read-only; edits, locks, Session state and original ALS bytes remain on existing command/recovery boundaries. Native file integrity still requires size and SHA-256 read-back. Browser file success is explicitly size-checked, not SHA-verified.

## Alternatives

- Increasing the memory cap: rejected; does not remove whole-output copies.
- Independently rendered segments: rejected; alters DSP state at boundaries.
- New native renderer: deferred; cannot substitute for the shared graph without separate parity and release qualification.

## Verification and rollback

Use the commands and evidence in REPORT.md. Byte equality applies to corresponding common PCM, not headers whose declared length now includes longer tails. Existing repeatability limits remain unchanged. Roll back the export/UI commits to restore the Blob route; no stored data rewrite is required. Do not advertise production Android, generic bounded-memory streaming synthesis, native-device sonic equivalence or producer-approved music from these checks.
