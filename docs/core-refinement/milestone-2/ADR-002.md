# ADR-002 — Canonical edit commits and portable project persistence

Status: implemented incremental G1 correction. Date:2026-11-02.

## Deficiency and decision

Four executable tests failed on M1: a typed note edit was absent from XML; mixer/automation/tempo/extent did not survive reload; clearing the last locator retained it; an invalid numeric mixer edit entered history. Existing command transactions synchronized only mixer annotations and locators.

Retain `AbletonProjectState`, current absolute-beat semantics, existing command bus, composition module and shared Web Audio graph. Add validation and incremental synchronization at the existing transaction boundary. Update supported typed MIDI content, scalar tempo and chosen extent; retain unchanged opaque clip XML. Serialize app-specific mixer and normalized `parametric:filter-energy` state in an explicitly versioned XML projection. Do not interpret unrelated native Hz/dB/parameter-target envelopes as one normalized curve. Preserve native envelopes and report a compatibility warning.

Command execution occurs outside React state updaters so StrictMode cannot replay side effects into history. A ref points to the same latest domain object for ordered batched commands; it is not another musical model. Undo/redo and queue records remain derived snapshots. More direct editing paths still require conversion; G1 is not complete.

Provide a version1 `.aidaw.json` project document containing the existing domain, original/derived XML and audio settings. Reopen validates before changing the active project, restores the domain without generation/humanization and gives it a fresh history key. External assets remain references; undo history and cross-process IndexedDB recovery are not promised. This file is the app's project format, not an Ableton fidelity certificate.

Use shared half-open clip eligibility and loop-boundary calculations in the existing engine. No new transport clock, generator or renderer. **Integer-tick migration and tempo/meter maps are not implemented here.** Introducing them still requires a separate migration/rollback ADR and executable engine/serialization parity fixtures.

## Migration and rollback

Existing XML without app metadata uses current parser defaults; unrelated native XML is retained. Unsupported versions of app metadata/native project files fail explicitly. New portable files have no legacy native-file predecessor to migrate. Keep original ALS and project files. Rolling back code to M1 does not give M1 a `.aidaw.json` reader: reopen using M2 and export the supported ALS subset if an older build is required. Do not delete the new project file or substitute a lossy ALS export for its backup.

## Validation and limitations

Command→XML→reload tests, no-mutation rejection, opaque native-envelope preservation, save→new→open UI workflow under StrictMode, future-version rejection, mixed clip length movement and production transport getter/scheduler tests. Browser CI adds an offline probability PCM oracle at44.1/48kHz, explicitly separate from live capture/listening approval. Full native device automation, new-track native materialization, arbitrary routing, all editing commands, sample assets, Session transitions and autosave recovery remain unqualified.
