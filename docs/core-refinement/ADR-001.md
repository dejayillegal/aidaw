# ADR-001 — Reuse clip serialization and isolate project history

Status: implemented incremental correction, 2026-11-02.

## Deficiency

Single-clip injection used unseeded random IDs. Multi-clip injection reused5000-based IDs across tracks and discarded unknown clip metadata. New Project reused the outgoing history key; full-suite composition flattened section boundaries.

## Decision

Retain `AbletonProjectState`, float-beat coordinates, the existing composer, transport and shared Web Audio graph. Delegate single-clip injection to the existing multi-clip serializer. Retain matching identities and opaque clip/note metadata; allocate numeric clip IDs against the document; persist application identities and exact grid coordinates as optional metadata. Newly materialized clips default to non-looping; retained imported loop flags/offsets are preserved.

Persist outgoing work and activate a distinct queue item for New Project. Apply existing section decomposition through the existing undo command. No new engine or timeline is introduced. Defer harmonic-planner expansion while G1 remains incomplete.

## Migration / rollback

Optional seed/identity/grid metadata requires no destructive storage migration. Old XML uses existing native IDs and inferred grids. Retain original raw XML and outgoing queue snapshots. Rollback is a revert of this milestone commit; previous parsers ignore optional attributes. Actual Ableton acceptance of application metadata remains unverified.

## Evidence / limits

Regression tests cover seeded XML replay, identities, probability, fine timing, short extents, Session exclusion, opaque clip subtrees, actual App composition round-trip and undo/redo. General ALS clip-local mapping, note-expression containers, tempo/meter maps and asset/routing fidelity need separate migration fixtures and an ADR before replacement.
