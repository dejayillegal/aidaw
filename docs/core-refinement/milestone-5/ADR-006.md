# ADR-006 — Stable native summation in the shared audio graph

Status: implemented candidate, verified locally; exact-head CI recorded in the associated PR. No replacement renderer, transport or composition engine.

## Confirmed deficiency and evidence

Same seed777/4bar canonical inputs produced intermittent native PCM differences above the existing max0.001 tolerance, including frame104031. The pre-audio correction checkpoint was otherwise executable. Twenty full-effects renders reproduced6 violations with max0.00225263834. Muting returns, removing insert delays, disabling oversampling, postponing disconnection and explicit compressor parameter/channel configuration did not consistently remove them. Master-compressor unity was a diagnostic control only. Fixed identical PCM through the native compressor produced zero differences; ordered binary summation of the original full graph also produced zero differences.

Chromium’s audio summing junction stores connections in a HashSet and copies them into a rendering vector; input processing sums that vector with floating-point unity additions. Sources: [junction header](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/modules/webaudio/audio_summing_junction.h), [junction implementation](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/modules/webaudio/audio_summing_junction.cc), [input summation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/third_party/blink/renderer/modules/webaudio/audio_node_input.cc). This supports the measured application-level cause: uncontrolled multi-source addition order, with tiny differences amplified by nonlinear master compression. This is not a claim of a Chromium specification violation or an uninitialized-memory defect.

## Decision

Keep the same native voices, native compressor and all parameters, native inserts, returns, scheduling windows and PCM/WAV paths. Route shared voice/track/send junctions through a stable binary tree of unity GainNodes. Group static multi-oscillator and master-return sums pairwise too. At most two inputs reach each arithmetic junction, so its addition is insensitive to native iteration order for finite samples. The tree adds no delay or processing substitute.

OrderedAudioSum owns DSP connections only. Its monotonic source index is not musical time or editable project state. Native stop times and existing audio-clock retirement boundaries govern leases. Released branches are pruned, and tree depth grows logarithmically; no fixed musical length or track count is introduced. The live and offline engines use the same helper. This does not prove bit-exact live-capture/offline parity for all project/edit/loop cases.

## Validation and limits

Unit controls demonstrate non-associative Float32 sums and invariance under reversed native input traversal, static sums, idempotent release, foreign-context rejection and10000 add/release operations without linear retained-tree growth. Native counterfactuals and production full-effects repeat renders are in native-dsp-experiments.json. The automated WAV regression expands from8 to20 repeats and now compares both channels with unchanged0.001/0.0001 limits. Native browser/Playwright versions are recorded.

Local production correction:20 raw stereo renders, max/RMS difference0. Full native harness:20 repeated WAVs with identical hashes,64bar export,48kHz mastering, probability oracle, recovery and responsive checks. Exact final CI must re-execute these. This does not certify true peak, DC/stereo/low-end behavior, expert listening, Android memory or commercial readiness.

## Migration, rollback and risk

No project schema, seed, note, preset, routing-gain or signing migration. Revert only the audio routing/helper changes to return to the prior graph, retaining the merge repair; the repeat defect would return. Keep original fixtures and unchanged tolerance tests as detection evidence. Stable floating-point grouping can choose a different compressor trajectory than one nondeterministic historical render. Listening approval is still required. Additional unity nodes increase CPU/allocation work; branch-resource tests are not native RSS/Android performance qualification. The existing256MiB render budget and tail limitations remain. The waveshaper is not advertised here as a qualified true-peak/lookahead limiter.
