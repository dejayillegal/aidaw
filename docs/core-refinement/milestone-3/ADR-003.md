# ADR-003 — Isolate command history and scope ALS verification claims

Status: implemented corrective subset in PR6. Preserves ADR-002, existing project model, command bus, timeline helpers, renderers and ALS preservation architecture.

## Confirmed deficiencies

getHistory copied only the transaction array, exposing nested before/after states to callers. executeMutation wrote revision/XML bookkeeping onto a mutator's returned object, which can be caller-owned. validateAlsProjectCadence inferred Pointee uniqueness from track uniqueness and asserted round-trip preservation and Live11/12 verification from syntax alone; a nonempty sidechain string was called valid without resolving its source.

## Decision

Return detached history snapshots and copy the mutator result before revision/XML bookkeeping. Keep the existing command architecture and supported transaction behavior. Inspect explicit Pointee IDs independently and resolve the simple SourceTrack subset against explicit track IDs. Leave unsupported native routing as unverified. Structural isValid is scoped to XML/hierarchy/track/Pointee identity, not executable routing or Live fidelity.

A single XML input cannot establish preservation or a semantic round trip. Set those unverified booleans false and explain NOT TESTED in diagnostics. Never emit Native Verified without native version-specific evidence.

## Limits and rollback

No schema migration, second state store, new engine or clock. Beat-based time, incomplete command coverage, tempo/meter/routing/assets/Session and native interoperability gaps remain. Full G1/G5 remain FAIL. Revert PR6's corrective commit to roll back; it makes no project-file version or signing changes. Reverting would restore the defects and false claims, so keep regression tests as detection evidence. Real Live fixtures/runtime and broader routing checks remain mandatory.
